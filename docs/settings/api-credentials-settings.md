# Harmonia API 密钥设置中心

## 产品目标

在 Harmonia 前台提供独立的「设置 → API 密钥」页面。后续所有第三方 API 凭据均由用户在此页面填写、验证、更新和删除；不要求用户进入 Cloudflare Dashboard 手工添加单个密钥，也不把密钥写入前端代码、Git 仓库或浏览器存储。

## 页面位置与信息架构

- 一级导航：设置
- 设置子页面：API 密钥
- 页面标题：API 密钥管理
- 页面说明：统一管理 Harmonia 外部数据源与服务的连接凭据。
- 首期提供 Actor 采集服务凭据；后续新增数据源时通过配置注册扩展，不把供应商字段写死在页面布局中。

## 首期表单

| 字段 | 说明 |
|---|---|
| 服务名称 | 采集服务 API |
| API Token | 用户输入的密钥，密码框显示；提交后不再回显明文 |
| 状态 | 未配置、待验证、已连接、验证失败、已停用 |
| 最近验证时间 | 最近一次服务端验证时间 |
| 最近验证结果 | 成功或可读的脱敏错误原因 |

页面操作：
- 保存并验证
- 重新验证
- 更新密钥
- 删除密钥

页面不得显示完整密钥；已保存时只显示「已配置」和末尾少量掩码字符（若确有必要）。接口不得返回密钥明文。

## 安全与后端要求

1. 前端只通过已认证 HTTPS API 提交凭据；不得将密钥写入 localStorage、sessionStorage、Cookie、URL、前端日志或分析事件。
2. Worker 服务端接收密钥后加密再持久化；加密主密钥仅存放在服务端 Secret binding。密文、nonce、算法版本分离存储，支持密钥轮换。
3. 每个用户的凭据按 user_id 隔离；所有读写均校验当前登录用户身份，不能信任请求体中的 user_id。
4. GET 接口只返回供应商、配置状态、掩码展示、验证时间和错误摘要，绝不返回密钥明文或密文。
5. 日志和异常必须脱敏；禁止记录请求 Authorization、API Token、完整请求体或上游敏感响应。
6. 保存、验证、更新、删除均写审计事件，但审计事件不得包含密钥内容。
7. 服务端验证连接时使用服务端保存的凭据；验证结果与密钥状态分开处理，避免把「已保存」误报为「已连接」。
8. 任何 API 密钥都不得提交到 GitHub、客户端 bundle、公开配置或数据库明文列。
9. RLS 必须按用户隔离凭据元数据；加密/解密只在受控服务端执行。
10. 删除密钥后清除可用凭据，并记录不含敏感值的删除审计事件。

## 验收标准

- 登录用户可以进入独立 API 密钥设置页。
- 用户可以保存、更新、验证、删除首期采集服务 Token。
- 刷新页面后仅展示配置状态，不重新显示明文。
- 用户 A 无法读取、覆盖或删除用户 B 的凭据。
- 浏览器网络响应、控制台、前端存储、应用日志和 Git 历史均找不到密钥明文。
- 上游验证失败时明确显示失败状态与脱敏原因，不误报成功。
- API 密钥设置页与采集任务运行状态相互独立；凭据未验证时不启动真实采集。
- 后续新增 API 服务可通过服务注册配置扩展，不需要重做页面结构。

## 当前实施前置条件

当前 main 分支只有基础 README 与数据库迁移文件，没有 package.json、前端入口、路由、UI 组件或现成的应用构建配置。因此本规格先作为实现基准；不能把此文档提交误报为已完成前端页面。开始页面与接口实现前，需要建立并验证正式应用骨架及部署链路。
